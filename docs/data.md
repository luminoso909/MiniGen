## **一、数据选择与任务对应**

数据的目的由研究问题决定。初期采用三层数据，MNIST 验证基础数学与训练器，合成图标测可控条件与泛化，真实图标检验现代模型领域适配。不同层级分别报告，不能互相替代能力证据。

| 数据 | 内容与规模 | 划分与使用 | 来源与限制 |
| --- | --- | --- | --- |
| MNIST | 28×28 灰度手写数字；基础阶段使用官方数据 | 官方训练部分再留出验证，官方测试部分仅最终评价；无条件扩散不把类别作为输入 | [Torchvision 加载器](https://docs.pytorch.org/vision/stable/generated/torchvision.datasets.MNIST.html)；小图验证不能代表彩色图标能力 |
| 合成几何图标 | 128×128 RGB；圆、方、三角形，四颜色，1–3 个非遮挡对象 | 10000 训练、1000 验证、1000 分布内、1000 组合外、1000 模板外 | 项目自生成；固定生成器版本与随机种子，描述从实际属性构造 |
| OpenMoji 子集 | 200–400 张统一风格图标，处理到模型所需尺寸 | 主体及近似变体先分组，再按组约 80/10/10 划分；逐图描述 | [官方仓库](https://github.com/hfg-gmuend/openmoji)、[许可](https://github.com/hfg-gmuend/openmoji/blob/master/LICENSE.txt)；元数据不一定包含完备视觉描述 |

OpenMoji 来源标为 CC BY-SA 4.0，保存出处、版本、署名和修改记录；素材许可与代码、预训练权重分别登记，不自动推断某个素材许可覆盖整个模型或项目。原始素材不默认随代码发布。

### **1. 收集与使用方式**

MNIST 使用显式下载入口，不在 import、doctor 或测试时自动下载。合成图标由确定性生成器产生，版本与配置可重建图像、标注和描述。OpenMoji 优先按固定版本获得选定素材和元数据，不无目的抓取全网图片，也不使用无来源图片补数量。

采集前登记预计数量、下载体积、原始和处理后占用、缓存占用及访问要求。原始数据保持只读，清洗结果写新版本。失败可重试，不覆盖已冻结版本；断点和错误记录由 Agent 维护。

### **2. 空间估算**

初期只给规划估算，采集后测量修正。14000 张 128×128 RGB 图像若按未压缩像素计算约 0.69 GB，实际 PNG 与几何复杂度有关；4×16×16 的 FP32 潜变量约 57 MB，且需先验证编码器实际形状。文本 token 缓存可能比潜变量更大，需单独统计。

MNIST 的原始、解压与处理副本分别计数。OpenMoji 先抽样测 PNG/SVG 和预处理后的体积，再按数量估算；模型权重占用单独记录，不能混进“数据只需要多少空间”的结论。

## **二、存储、清单与版本**

### **1. 图片文件加 JSONL**

真实内容放项目根目录 `data/raw/`、`data/processed/`、`data/manifests/`，缓存放 `artifacts/cache/`。JSONL 是样本清单事实来源，YAML 是数据来源登记；SQLite 暂不引入，未来若需要查询只能从清单重建索引。

每条真实记录包含 sample_id、相对 data 根目录的 image_path、source_id、source_revision、SHA-256、宽高、模式、描述、描述来源、属性、group_id、split、schema_version，以及必要的署名引用。路径不允许指向 data 根目录之外。

示例见 [manifest.example.jsonl](../configs/examples/manifest.example.jsonl)。该记录是占位示例，`example_only: true`、文件哈希为 null，不对应真实图片；正式加载器必须拒绝示例记录和缺失哈希。

### **2. 可重现版本**

记录下载日期、上游 revision 或归档哈希、生成器版本、过滤规则、划分种子和原始到处理后的映射。上游只写 latest 不构成可复现版本，来源未固定时状态保持 planned。

编码缓存记录 VAE、编码模式、缩放、dtype 和图像预处理；文本缓存记录 tokenizer、文本编码器、长度、mask 和描述版本。数据或组件变化产生新缓存版本，不凭同名文件跳过验证。

真实数据、生成清单与索引默认忽略；提交来源登记、清单示例、生成配置、数据卡和小型聚合报告。JSONL 哈希不包含个人绝对路径，跨设备通过相对路径重建定位。

## **三、质量流水线与验收口径**

流程为：登记来源 → 小样本获取 → 校验解码 → 规范格式 → 去重与分组 → 划分 → 描述审核 → 质量报告 → 冻结版本 → 缓存。

| 检查 | 处理方式 | 冻结要求 |
| --- | --- | --- |
| 解码与格式 | 检查损坏、尺寸、通道、透明背景和朝向 | 最终清单中的样本全部可用 |
| 字段与内容 | 唯一 ID、有效路径、描述、来源、哈希与划分 | 必要字段完整；示例不得混入 |
| 重复与变体 | 文件哈希、近似重复与主体分组 | 完全重复与同组不跨集合；近似项有复核记录 |
| 分布 | 按颜色、形状、数量、关系和主体统计 | 公开筛除前后数量与空缺，不偷偷补测试样本 |
| 描述 | 与可见内容核对，检查方向、数量和不存在属性 | 合成描述准确生成；真实描述抽查与修订可追踪 |
| 表示保留 | 原图与 VAE 重建的关键属性比较 | 属性已丢失时先修数据或表示，再训生成主干 |

Agent 自动执行全量结构检查，并对真实图标描述做至少 10% 且不少于 30 张的分层抽查；初期你只需复核代表性样本、争议样本与总结。发现错误后扩大对应类别抽查，记录修订，不把 AI 自评当成独立人工验证。

## **四、划分、增强与防泄漏**

合成数据保留红色三角形、蓝色方形为组合外属性；各单独颜色和形状在训练中出现。组合外测试使用已见表达模板，模板外测试使用已见视觉组合，两种变化分别衡量。独立种子不能代替重复检查。

OpenMoji 先分组再切分，变色、肤色和近似主体版本不跨集合。训练可使用的增强必须保留主体和标注；方向描述遇到翻转时同步更新或禁用，裁切不得无记录改变数量。验证只用于选型，测试在选型冻结后统一评价。
