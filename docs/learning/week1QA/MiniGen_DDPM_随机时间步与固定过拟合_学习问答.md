# MiniGen｜DDPM 随机时间步与固定批次过拟合：学习问答

> 本页针对当前 MNIST + `TeachingDDPMScheduler` + `TinyUNet` 实验。**代码索引 `t=0` 是数学的第一步加噪**；以下按代码索引叙述。

## Q1. 为什么训练时随机采样时间步，而不是从 0 到 999 顺序迭代？每个时间步训练哪些参数？

**核心结论：**扩散的*定义*是一条逐步加噪马尔可夫链，但*训练时构造样本*可直接跳到任何时间：

$$x_t=\sqrt{\bar\alpha_t}x_0+\sqrt{1-\bar\alpha_t}\,\epsilon,\quad \epsilon\sim\mathcal N(0,I).$$

`Scheduler.add_noise(x0, eps, t)` 可以一次构造任意 `t` 的带噪图，**不需要逐个执行之前的加噪步骤**。直接加噪与顺序加噪在给定 `x0` 下具有相同分布，不保证同一份随机结果。

**随机时间的作用：**让同一个 U-Net 在每次训练中接触不同噪声等级，尽早覆盖从轻微噪声到近乎纯噪声的任务；用少量时间样本估计所有时间步的平均训练目标。

例如，`B=4`：

```python
x0 = images[:4]                       # [4,1,28,28]
t = torch.tensor([10, 200, 600, 999])  # [4]，每张图不同时间
eps = torch.randn_like(x0)              # [4,1,28,28]
xt = scheduler.add_noise(x0, eps, t)    # [4,1,28,28]
eps_pred = model(xt, t)                 # [4,1,28,28]
loss = F.mse_loss(eps_pred, eps)
optimizer.zero_grad(); loss.backward(); optimizer.step()
```

**每个时间步并没有独立网络或独立参数集。**四个时间步共享同一份 `TinyUNet` 参数 `θ`（此前实验中共 654,785 个可训练参数），`loss.backward()` 累积整个 Batch 对这套参数的梯度。时间 `t` 经固定 Sin/Cos 编码、可训练 TimeEmbedding MLP 和各 TimeBlock 的独立时间投影改变网络的运算。`beta/alpha/alpha_bar` 则属于固定的 Scheduler 查找表，不由优化器更新。

可以用最简单的数值例子理解平均：假设只有三个时间步，各步期望损失分别是 `0.2、0.5、0.8`，均匀抽 `t` 时，抽到的单次损失可能是其中任何一个，但它的期望是 `(0.2+0.5+0.8)/3=0.5`，等于三步平均损失。**不意味着每次随机抽取的损失都等于 0.5**。

$$L(\theta)=\frac1T\sum_{t=0}^{T-1}\mathbb E_{x_0,\epsilon}\|\epsilon-\epsilon_\theta(x_t,t)\|^2.$$

顺序枚举时间步同样可行，并非绝对错误；随机抽样的优点是计算方便、混合噪声难度、适合随机梯度优化。如果所有时间步在同一次更新中都计算，成本通常很高；只按顺序每步选一个 `t`，短期数据会偏向当前噪声级别。

## Q2. 训练图到底说明了什么？画的是 Train Loss 还是 Validation Loss？

**你的图是固定训练配对（fixed-pair）的损失曲线，不是验证集曲线。**实验反复使用 `fixed_x=images[:16]`、**固定** `fixed_eps`、**固定** `fixed_t=250`，训练同一映射 `(xt, t) → eps`，故刻意做的是小批次过拟合调试。

实际截图数据：

| 指标 | MSE | 含义 |
|---|---:|---|
| 训练前固定 Probe | 1.0771077 | 未训练模型在这 16 张固定数据上的误差 |
| 第 50 步训练日志 | 0.07591 | 当时的固定配对损失 |
| 第 100 步训练日志 | 0.01059 | 当时的固定配对损失 |
| 训练后固定 Probe | 0.0099809 | 再次在原来的固定三元组上测量 |
| **训练后，新抽噪声** | **0.0843838** | **同 16 张原图、同 t=250，但换了噪声** |

固定 Probe 损失比例：`0.0099809 / 1.0771077 ≈ 0.00927`，即最终仅为初始的约 **0.93%**，下降约 **99.07%**。这证明**固定监督映射可以被模型拟合、优化链路能工作**，不是模型已学会所有时间步或能生成新图片。

**为什么新噪声 Loss 会变高？**输入的带噪图与监督标签变了，模型没直接记忆过这批具体噪声；`0.08438` 比固定 Probe 的 `0.00998` 大约 **8.45 倍**，说明在新噪声上表现明显弱一些。但它又比训练前的固定 Probe `1.0771` 小得多，提示模型在此时间/这些原图上可能学到一些可迁移规律。不能拿跨实验条件的不同 Loss 宣称严格的泛化提升，需要进一步控制变量。

**区分三个层次：**

1. **训练集/训练配对 Loss**：参数更新所用的样本，当前图属于此类；固定 Probe 虽单独命名，但与训练数据相同，不算独立验证。
2. **未见噪声 Loss**：保持原图与时间不变，只换新的 `eps`；它是一种有限的局部泛化测试。
3. **独立验证集 Loss**：使用 `val_loader` 中没有参与训练的 `x0`，并抽取新的时间和噪声；更能检验跨图片、跨噪声级别的泛化，但仍不直接等于生成质量。

### 下一个具体测试（可直接运行）

```python
model = overfit_model.to(DEVICE).eval()
scheduler = TeachingDDPMScheduler().to(DEVICE)
val_images, _ = next(iter(val_loader))
x0 = val_images[:16].to(DEVICE)                     # 未参与该固定批次训练的图片
t = torch.randint(0, scheduler.num_steps, (len(x0),), device=DEVICE)
eps = torch.randn_like(x0)
with torch.no_grad():
    xt = scheduler.add_noise(x0, eps, t)
    val_loss = scheduler.loss(model(xt, t), eps)
print('独立验证批次的随机 t/noise MSE:', val_loss.item())
```

注意：这个过拟合模型只在 `t=250` 上训练，故独立验证批次采用随机 `t` 时，即使损失偏高也是预期现象，**不等于代码有 Bug**。正式模型要对训练集反复抽取不同时间步和噪声训练，然后再评价验证 Loss 与从纯噪声生成的结果。

### 易错点

- **训练用随机 t ≠ 顺序加噪 1000 次。**训练只需用预计算的 `alpha_bar[t]` 一步构造 `xt`；**生成**时才在此 DDPM 实现中逐步调用 `step`。
- **一次优化步骤 ≠ 一个扩散时间步。**`optimizer.step()` 更新神经网络权重；`t` 表示噪声级别。
- **固定 Probe ≠ 验证集。**只要 Probe 与反复训练用的固定三元组相同，它就不独立。
- 第 100 步日志 Loss 与训练后 Probe Loss 可以略有差异，取决于日志记录位于优化器更新前还是更新后。

**一句话复习：**随机 `t` 让**同一个 U-Net**学会各种噪声水平；固定 16 图的下降曲线证明训练链路能拟合，**不证明独立验证或生成质量**。
