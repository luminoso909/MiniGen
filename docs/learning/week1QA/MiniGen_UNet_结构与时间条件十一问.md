# MiniGen · U-Net 结构与时间条件十一问

> **扩充版说明**：保留原问题与核心答案，额外增加直觉、数值例子、代码对照与延伸。推荐先读每问的粗体结论，需要时再展开补充。


> 对应代码：`TimeEmbedding`、`TimeBlock`、`TinyUNet`。以下只针对当前 MNIST 无条件噪声预测 U-Net。

### 1. `time_width`、`timesteps` 有何区别？为什么是 128？
`timesteps` 是每张图的**整数噪声时间索引**，形状 `[B]`；`time_width=128` 是**时间特征维度**（超参数），不是时间步数量。编码流程：`[B] → sin/cos [B,128] → MLP [B,128] → TimeBlock.Linear(128,C_out) → [B,C_out,1,1]`，再与 `[B,C_out,H,W]` 广播相加。128 是容量与开销的折中，并非必须；固定频率不是随机矩阵，但 MLP 与时间投影初始为随机可训练参数，会通过 loss 学习。

#### time_width 不是时间步个数

例：`timesteps=torch.tensor([0,999])` 形状 `[2]`，其中两个整数是“噪声程度索引”；`time_width=128` 表示每个整数将被编码成 128 维特征。路径是 `[2] → sin/cos [2,128] → MLP [2,128] → Linear(128,C_out) → [2,C_out,1,1]`。

`SinCos(t)` 是确定的，不是乱数；**随机初始化**的是后续 MLP 和各 TimeBlock 的时间投影层。训练后，相同 $t$ 会生成稳定的、被模型利用的时间调节向量。最后的 Linear 既做维度匹配，也让**每一层学出不同的时间响应**。

**小例子：** 时间投影输出某张图的两个通道偏移 `[0.2,-0.5]`，便对该图对应两张特征图的**每个空间位置**分别加 0.2 和减 0.5。它不是 128 个时间值和 28×28 像素直接相加。

### 2. GroupNorm 究竟按什么范围归一化？
对输入 `[B,C,H,W]`，`GroupNorm(G,C)` **每张图、每组通道独立**计算均值/方差；一组含 `C/G` 个通道，统计元素数是 `(C/G)×H×W`，**不跨 batch、不跨组**。公式：`x̂=(x−μ_{b,g})/sqrt(σ²_{b,g}+eps)`，输出 `γ_c x̂+β_c`；`γ,β` 可学习。`GroupNorm(8,64)` 每组 8 个通道。LayerNorm 归一化哪些轴取决于 `normalized_shape`，不总是“最后一维”。

#### 用 2×2 的微型例子亲手算 GroupNorm

假设单张图、两个通道、**1 个组**，张量元素分别是 `channel0=[1,2]`、`channel1=[3,4]`（可以看成 $H=1,W=2$）。整个组共有 4 个元素：

$$\mu=(1+2+3+4)/4=2.5,\quad \sigma^2=[(-1.5)^2+(-0.5)^2+0.5^2+1.5^2]/4=1.25.$$

忽略 `eps` 且暂设 $\gamma=1,\beta=0$，归一化结果近似 `[-1.342,-0.447,0.447,1.342]`。**跨越了组内的两个通道及其所有空间位置**；如果换成两个组，就会在每个通道内部单独计算统计量。

注意 PyTorch `GroupNorm(G,C)` 要求 $C$ 能整除 $G$，并且每个样本、每个组独立计算，不跨 Batch。与 Token 上常用的 LayerNorm/RMSNorm 关注维度不同。

### 3. 为什么有三处 SiLU？
当前顺序是：`Conv1 → GN1 → SiLU → +time_bias → SiLU → Conv2 → GN2 → +skip(image) → SiLU`。第一处为首段特征引入非线性；第二处让**加过时间条件**的特征再经非线性后进入卷积；第三处激活残差融合结果。不是必须恰好三处，也没有必须对称的原则；它是设计选择。`GN2` 后立即加残差再统一 SiLU。

#### 三次 SiLU 不是重复计算同一份数据

此代码的真实顺序：`Conv1 → GN1 → SiLU① → +Time → SiLU② → Conv2 → GN2 → +Residual → SiLU③`。

① 第一轮卷积特征的非线性；② 时间偏置改变了输入，新的非线性让时间更容易影响后续卷积的响应；③ 融合残差后，再对两条路径的和施加非线性。

**数值直觉：** 若某特征是 `0.3`，时间偏置为 `-0.8`，相加后是 `-0.5`，经过 SiLU 变成约 `-0.189`；和“只加一个常数然后保持线性”不同。把③换到残差相加之前也是可设计的方案，并非必须对称，也不能仅凭层数判断哪个更优。

### 4. `skip` 为什么是 1×1 Conv，而不是 Linear？
`1×1 Conv2d(C_in,C_out)` 本质是**对每个像素位置共享同一个从 `C_in` 到 `C_out` 的线性变换**，原生支持 `[B,C,H,W]`，不改变 H/W。`nn.Linear` 理论上也能做等价操作，但须先调整通道位置等，1×1 Conv 更直接。

#### 1×1 Conv 就是每个位置共享的线性映射

假设输入 `[B,2,H,W]`，输出 `[B,3,H,W]`。某个位置的向量是 $[x_1,x_2]$，它会被同一矩阵 $W\in\mathbb R^{3\times2}$ 变成 3 维；下一个像素位置**复用相同矩阵**。不会混合相邻像素。

`nn.Linear(2,3)` 也能做，但更习惯接收 `[B,H,W,2]`，需要 `permute`；`Conv2d(2,3,1)` 可以直接处理 `[B,2,H,W]`。这里 `skip` 负责让残差分支的通道数匹配主分支；**不是 U-Net 横跨 Encoder/Decoder 的那个 skip**。

### 5. `base` 是什么？
`base=32` 指网络的**基础特征通道数**，不是 batch、token 数、像素数。此 U-Net 的特征通道大致按 `32 → 64 → 128 → 64 → 32` 变化。增加 `base` 会增加容量及参数/计算成本；当前 GroupNorm 要求相应输出通道能被 8 整除。

#### base 加倍会怎样？

`base=32` 意味着主要通道为 `32 → 64 → 128 → 64 → 32`；改为 `base=64` 就变成 `64 → 128 → 256 → 128 → 64`。因此 `base` 类似 CNN 的基础宽度，与 `B`（batch size）、H/W（空间尺寸）无关。

卷积权重数约为 $C_{out}\times C_{in}\times K^2$（再加偏置）；中间大部分卷积的输入输出通道都随 `base` 增大，所以参数/计算成本往往近似随宽度的平方增长，**不保证整网严格乘四倍**（因为还有时间投影、首尾层等）。

### 6. TimeBlock 输出什么？为什么多次加入时间？
`TimeBlock(image,time)` 输出 `[B,C_out,H,W]` 的**中间特征图**，不是直接输出噪声（最终 `TinyUNet.out` 才映射到 1 通道噪声）。不同时间步噪声强度不同，各尺度的特征处理都需要知道当前时间；多次加入时间可以让每一层按噪声级别调整特征。它不是“把同一份原始时间数据瞎加”——每个 TimeBlock 有自己的可训练 `Linear(time_width,C_out)`。

#### TimeBlock 不输出图片，也不单独输出噪声

例如 `TimeBlock(32,64,128)` 输入图像特征 `[2,32,14,14]` 与时间特征 `[2,128]`，输出的是 `[2,64,14,14]` 的**下一层特征**。它融合空间局部信息、时间条件和残差，仍然是中间表示；只有 `TinyUNet.out` 才把通道压到 `1`，得到噪声预测。

为什么多层都加时间？不同噪声水平需要不同的处理策略；低层提取局部模式，高层整合更大范围信息，每层用自己的 `Linear(time_width,C_out)` 学习时间调节。**这是设计选择，不是数学规定每一层必须加时间**。现代模型还常见缩放+平移的条件调节，而不是只做加法。

### 7. 下采样和上采样是什么？为什么先下再上？
**下采样**减小 H/W：本例 `Conv2d(k=4,stride=2,padding=1)` 把 `28→14→7`，卷积同时学习特征。**上采样**增大 H/W：`F.interpolate(...,size=...,mode="nearest")` 把 `7→14→28`，本身不学习参数。先下使后续层以较小成本整合较大范围信息；再上恢复每像素的预测分辨率。图像分类 CNN 常常只下采样；需要密集输出的 U-Net 才典型地下后上。

#### 用真实 Shape 解释“下再上”

```text
[B,1,28,28] → enc1 [B,32,28,28]
            → down1[B,32,14,14] → enc2[B,64,14,14]
            → down2[B,64,7,7]   → middle[B,128,7,7]
            → upsample[B,128,14,14] → dec2[B,64,14,14]
            → upsample[B,64,28,28]  → dec1[B,32,28,28]
            → out[B,1,28,28]
```

`down1=Conv2d(k=4,stride=2,padding=1)` 按输出尺寸公式把 $28\to14$；`interpolate` 再把 $7\to14\to28$。下采样使深层每个位置整合原图更大范围的信息；上采样恢复像素级预测所需的空间网格。**上采样不会魔法般找回所有丢失信息**，因此要通过跨层 Skip 补充。

扩展：分类 CNN 常一路下采样后做全局池化；U-Net 用于分割/去噪这样的密集输出，因此需要恢复 H/W。

### 8. 为什么有两种 skip？
**TimeBlock 内的残差 skip**：`hidden + Conv1×1(image)`，同一层内逐元素相加，促进信息和梯度传递；**U-Net 长跳连**：`cat([hidden,skip2],dim=1)` 等，把 Encoder 特征送给 Decoder，保留高分辨率细节。都称 skip，是因为信息绕过中间一些运算走捷径，但一个是**加法**，另一个是**通道拼接**。

#### 两种 skip，运算方式不一样

- **TimeBlock 内部**：`hidden + Conv1x1(image)`，逐元素相加；像一个短捷径，支持特征和梯度传播。
- **U-Net 两侧**：`cat([hidden, skip2], dim=1)`，通道拼接；像一座跨越瓶颈的桥，把编码端高分辨率特征送到解码端。

例如 decoder 上采样结果 `[2,128,14,14]` 与 `skip2=[2,64,14,14]` 拼接，得到 `[2,192,14,14]`。若改成 `+`，通道不同会报错；也会失去“保留两组特征供后续学习融合”的直接形式。

### 9. `enc1=TimeBlock(1,base,...)` 是否只能接灰度图？
对，当前写死单通道输入和输出：`enc1` 的 `in_channels=1`，`out` 的 `out_channels=1`。若改 RGB 噪声预测，应把第一层输入和最后一层输出都改为 3，并提供 `[B,3,H,W]` 图像与同形状噪声；其他通道设置通常不必因 RGB 而变。

#### 修改 RGB 时只改两个接口

```python
self.enc1 = TimeBlock(3, base, time_width)
self.out  = nn.Conv2d(base, 3, 3, padding=1)
```

当前任务是预测输入图片中同形状的噪声，灰度图输出 1 通道，RGB 则输出 3 通道。`base=32` 仍可保持不变。但如果要生成更大分辨率的 RGB 图片，训练数据、显存成本、感受野等也要重新评估，**改两个通道数只是“接口能运行”的必要部分，不代表生成质量自动成立**。

### 10. `interpolate` 的输入输出是什么？
`F.interpolate(hidden,size=skip2.shape[-2:],mode="nearest")` 把 `[B,C,7,7]→[B,C,14,14]`；只改变空间尺寸，不改变 B 或 C。`nearest` 用最近邻原值填充新增位置；与 `torch.cat` 配合，保证 Decoder 特征的 H/W 与 Encoder 的 skip 特征相同。

#### 最近邻上采样的数值例子

$$\begin{bmatrix}1&2\\3&4\end{bmatrix}\xrightarrow{\mathrm{nearest},\ 2\times}\begin{bmatrix}1&1&2&2\\1&1&2&2\\3&3&4&4\\3&3&4&4\end{bmatrix}.$$

```python
x = torch.tensor([[[[1.,2.],[3.,4.]]]])
y = F.interpolate(x, size=(4,4), mode='nearest')
assert y.shape == (1,1,4,4)
```

**它只改变 H/W，不改变 B/C，没有可训练权重。** `size=skip.shape[-2:]` 的用处是确保解码端空间尺寸与 Encoder Skip 一致；否则 `torch.cat(...,dim=1)` 无法拼接。

### 11. 为什么第一周不要求从零手写 U-Net？
本阶段主要验收 **DDPM 的加噪、目标函数、Scheduler 与采样闭环**；U-Net 是可替换的噪声预测器。先使用已有小 U-Net 能隔离学习难点、节约时间，后续更有必要把精力放在 DiT 核心实现。不过应能看懂每个 TimeBlock、尺寸变化并做小改动；“不必从零写”不等于“不必理解”。

#### 学习优先级不是“重要性排行榜”

第一周要先打通 `加噪 → 模型预测 → MSE → 反向采样`。手写 Scheduler 能迫使你面对 $\alpha/\bar\alpha$、时间索引、广播、反向均值等**扩散算法本身**的问题；从零写 U-Net 还会叠加卷积网络、跳连、归一化调试，分散注意力。

建议验收：能够手画 U-Net 数据流，独立说出两类 Skip、TimeEmbedding 和 TimeBlock 的形状，能把灰度接口改为 RGB 并通过 Shape 测试。更深入的从零实现投入到后续 DiT、条件注入和 Flow 目标上，更符合 MiniGen 的目标与时间预算。

## 一眼记住的数据流

- 时间：`timesteps [B] → TimeEmbedding [B,128] → 各 TimeBlock 时间投影 [B,C,1,1]`。
- 图像：`[B,1,28,28] → enc1 32×28×28 → enc2 64×14×14 → middle 128×7×7 → dec2 64×14×14 → dec1 32×28×28 → out [B,1,28,28]`。
- **时间条件影响各层如何提特征；最终输出是一张与输入等形状的预测噪声图。**
