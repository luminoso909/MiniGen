## **一、工程阶段与个人学习**

工程由 P0–P7 的依赖和验收推动，个人课程按 S4–S7 逐课推进。先确认用户本轮启动的阶段、读取工作树和当前交接，再做该阶段可验证的最小任务。当前以 [v2 重构规划](MiniGen2重构规划.md)、[学习目录](MiniGen2学习目录.md) 与 [交接](../reports/v2/00_handoff.md) 为入口。

用户负责核心 TODO、原理和研究判断。Codex 负责数据、工程、独立测试、调试、执行与文档。按授权提供参考或工程实现时，记录代码来源。个人核心验收、教学运行、工程短跑、生成质量和正式实验分别登记。首份 S4-01 在学习回合获准后交付。

## **二、每回合闭环与验收**

1. 读取规格、当前交接、适用指令和实际代码，确定已满足的依赖。
2. 按 [任务模板](../templates/task.md) 记录文件归属、输入输出、验收和资源上限。
3. 保留用户改动与历史产物，对照五份 Notebook 的 SHA-256。
4. 分别验证数学与行为、数据与组件、训练/恢复和评价。记录命令、版本、设备、输出及失败。
5. 按 [交接模板](../templates/handoff.md) 更新 `reports/v2/00_handoff.md`，给出一个下一优先任务及需用户决定的选择。

P1 的 ArtBench 验收包含全量结构检查和配对图文抽查，记录代理审核与人工确认的各自来源。P2 的 200 张 VAE 重建分别记录数值、代理视觉检查与用户审核。试点缓存可以提前验证接口；正式缓存须绑定此次用户审核和本机固定 20 张验收回执。冻结前向编码的本机正确性与后续 CUDA 训练运行验收单独记录。正式长训前独立核对个人核心理解/测试、工程短跑、数据与组件及用户预算批准。MiniGen-Bench 提示词、噪声种子和评分协议在正式训练前冻结。对失败样本保留分母与记录，自动评分先与人工校准。

## **三、按职责并行**

按用户授权或适用指令决定是否并行。主 Agent 划分互斥文件与稳定接口，集成后亲自复验。

| 角色 | 交接重点 |
| --- | --- |
| [数据](../templates/role-data.md) | 来源、规范、清单、划分与失败记录 |
| [工程](../templates/role-engineering.md) | 模块契约、测试、短跑和恢复 |
| [评测](../templates/role-evaluation.md) | 固定协议、分母、人工校准和效率 |
| [审查](../templates/role-review.md) | 实际证据、回归、遗留与风险 |

## **四、资源与发布**

本地检查优先用已有环境。数据、模型与源码获取使用显式固定版本的命令。收费资源及可能产生成本的批量获取先给出 dry-run 与成本估算，由用户批准后执行。记录实际费用和 GPU 时间。Git 操作按任务授权，提交与推送各自限定范围。历史执行和证据见 [报告导航](../reports/README.md)。
